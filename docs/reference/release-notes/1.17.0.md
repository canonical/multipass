# 1.17.0

These release notes cover new features and changes in Multipass 1.17.0.

Multipass 1.17.0 is a large feature release. Besides a variety of small improvements, it introduces Availability Zones for resilient, zone-aware instance placement, and adds official support for Debian and Fedora images alongside Ubuntu.
On the platform support side, a new Windows driver was built based on the Host Compute System (HCS) APIs which works on all editions of Windows and makes the support for Hyper-V and VirtualBox obsolete. On macOS, this version introduces a preview of a new driver based on the Apple Virtualization framework, which will eventually replace QEMU and VirtualBox altogether.

This release completes the deprecation cycle announced in 1.16 by removing the LXD and libvirt drivers, blueprints, and appliances.

## New features & improvements

### Availability Zones for local cloud simulation

Virtual machine instances can now be placed in named availability zones using `multipass launch --zone` to locally simulate a cloud environment by placing each virtual machine in an availability zone. Each zone has its own isolated subnet, and instances in a zone that loses connectivity are marked unavailable instead of failing silently. The `multipass disable-zones` and `multipass enable-zones` commands can be used to toggle zone availability and `multipass zones` to list and view zone availability.

Availability Zones are supported on QEMU (Linux and macOS), the new Apple Virtualization framework on macOS, and on the Host Compute System (HCS) backend on Windows. When upgrading to Multipass 1.17, existing instances are placed into zone 1 automatically.

### Built-in Debian and Fedora support

Building on the custom image support introduced in the previous release, Multipass 1.17 adds direct support for Linux distributions other than Ubuntu, in particular for Debian and Fedora. We are opening the door for other distributions such that users can benefit from these as new playgrounds. We'd love to get feedback from our users if that direction is worth exploring more in the future.

### Redesigned image catalog

The main screen of Multipass' GUI has been redesigned and groups releases per operating system leading to a compact view and improved usability.

### New Host Compute System (HCS) driver on Windows

The new default driver on Windows is implemented on top of the Windows Host Compute System (HCS) APIs, replacing the previous Hyper-V-based integration with a more robust native foundation. The main benefit of the new driver is its support across all editions of Windows, including  Windows Home. This change allows us to deprecate the VirtualBox and Hyper-V drivers on Windows. A migration path to upgrade existing Hyper-V virtual machines is available. For VirtualBox instances, there is no automatic migration path foreseen.

### New Apple Virtualization framework backend on macOS

On macOS, a new driver based on Apple's Virtualization framework is offering faster startup and native ASIF disk image support on macOS 26. While this driver is still in preview, we continue to support QEMU and VirtualBox (Intel/x86 only). The new driver is Multipass' future default driver and once it supports all of Multipass' features, other drivers will be deprecated.

### New CPU architectures: ppc64el and s390x

Multipass now builds and runs on Linux on IBM POWER (ppc64el) and Z (s390x) machines, with official snaps published for both architectures.

### Other improvements and noteworthy changes

- For scripted and automated environments, the new `multipass wait-ready` command is particularly helpful to block until the daemon/service is ready and CLI commands can be executed.
- Launching virtual machines using cloud-init now supports rebooting the instance.
- `multipass exec` now returns the exit code of the command run inside the instance.
- Certificates for the client-daemon connection are now annotated and automatically regenerated which also includes improved reporting on client authentication errors.
- Minimum resources for new instances have been raised to 512 MiB of memory and 1 GiB of disk, preventing silent cloud-init failures on undersized launches.
- The Windows executables now carry version information.
- The macOS installer is more robust when downgrading or reinstalling, and the uninstaller also removes client certificates and GUI data.

### GUI improvements

- The latest Ubuntu LTS release is selected by default.
- The memory and disk size sliders in the configuration form adapt to the selected image type.
- The terminal remembers its font size, and offers a "Select All" context-menu entry.
- The About section in the Settings tab provides information about the Multipass version in use.
- The GUI was prepared for localization.

## Removed functionality

The following features, deprecated in Multipass 1.16, have been removed:

- Blueprints and Appliances
- The LXD and libvirt drivers
- The `mem` shortcut for the `--memory` option
- The `--all` option of `multipass info`

## Breaking changes

- CLI exit codes were unified: `multipass shell` and `multipass exec` propagate the exit code of the in-instance command, while 255 is reserved for Multipass' own failures
- Mount target paths are fully normalized before use; in particular, trailing slashes are now trimmed
- Symlinks in mounts that point outside the mounted folder are now denied
- Key ordering in `--format json` output is no longer guaranteed
