(1.17.0)=
# 1.17.0

These release notes cover new features and changes in Multipass 1.17.0.

Multipass 1.17.0 is a major release. It introduces Availability Zones for resilient, zone-aware instance placement; adds official support for Debian and Fedora images alongside Ubuntu; brings Multipass to the ppc64el and s390x architectures on Linux; and introduces a brand new Apple Virtualization.framework backend on macOS. On Windows, the Hyper-V driver was rebuilt on the Host Compute System APIs. This release also completes the deprecation cycle announced in 1.16 by removing the LXD and libvirt drivers, blueprints, and appliances, and it upgrades the bundled QEMU to version 10.

## New features & improvements

### Availability Zones

Multipass instances can now be placed in named availability zones (`multipass launch --zone`), with new `multipass zones` commands to list and manage zones. Each zone gets its own isolated subnet, and instances in a zone that loses connectivity are marked unavailable instead of failing silently. Availability Zones are supported on QEMU (Linux and macOS), the Apple Virtualization.framework backend, and Hyper-V. ([#4312](https://github.com/canonical/multipass/pull/4312), [#5056](https://github.com/canonical/multipass/pull/5056), [#4931](https://github.com/canonical/multipass/pull/4931), [#4967](https://github.com/canonical/multipass/pull/4967))

- Instances migrate into their original subnet on upgrade, so existing instances keep their IP addresses ([#5031](https://github.com/canonical/multipass/pull/5031), [#4894](https://github.com/canonical/multipass/pull/4894))
- `multipass delete` (including `--all`) can now remove instances in the `unavailable` state ([#4996](https://github.com/canonical/multipass/pull/4996))
- Cross-zone VM-to-VM networking on macOS ([#5063](https://github.com/canonical/multipass/pull/5063))
- Zone subnets are shown in `multipass zones` output, and zone names are pre-validated in the CLI ([#4969](https://github.com/canonical/multipass/pull/4969), [#5103](https://github.com/canonical/multipass/pull/5103))
- Subnet allocation checks that candidate subnets are not already in use ([#4675](https://github.com/canonical/multipass/pull/4675))
- Virtual switches and subnets are created per zone on Linux and macOS, and fixed where the feature flag previously left them misconfigured ([#4650](https://github.com/canonical/multipass/pull/4650), [#4688](https://github.com/canonical/multipass/pull/4688), [#4840](https://github.com/canonical/multipass/pull/4840))

### Debian and Fedora images

`multipass find` and `multipass launch` now offer official Debian and Fedora cloud images next to the Ubuntu images, with release names shown in listings. Ubuntu Core images moved to the SimpleStreams image host, and the snapcraft image catalogue is filtered to supported images only. ([#4293](https://github.com/canonical/multipass/pull/4293), [#4495](https://github.com/canonical/multipass/pull/4495), [#4438](https://github.com/canonical/multipass/pull/4438))

### New CPU architectures: ppc64el and s390x

Multipass now builds and runs on Linux on IBM POWER (ppc64el) and Z (s390x) machines, with official snaps published for both architectures. ([#4644](https://github.com/canonical/multipass/pull/4644), [#4548](https://github.com/canonical/multipass/pull/4548), [#4893](https://github.com/canonical/multipass/pull/4893), [#4822](https://github.com/canonical/multipass/pull/4822), [#4890](https://github.com/canonical/multipass/pull/4890))

### New Apple Virtualization.framework backend on macOS

A new backend based on Apple's Virtualization.framework is available on Apple silicon Macs, offering faster startup and native ASIF disk image support on macOS 26, with support for multiple network interfaces. ([#4653](https://github.com/canonical/multipass/pull/4653), [#4542](https://github.com/canonical/multipass/pull/4542), [#4676](https://github.com/canonical/multipass/pull/4676), [#4757](https://github.com/canonical/multipass/pull/4757))

- Clear errors when an operation (e.g. snapshot, suspend) is not supported by this backend, and correct instance state after a daemon restart ([#4766](https://github.com/canonical/multipass/pull/4766))

### Rebuilt Hyper-V driver on Windows

The Hyper-V driver was reimplemented on top of the Windows Host Compute System (HCS) APIs, replacing the previous PowerShell-based integration with a more robust native foundation. ([#4080](https://github.com/canonical/multipass/pull/4080))

### Other improvements

- New `multipass wait-ready` command to block until an instance has finished initializing ([#4304](https://github.com/canonical/multipass/pull/4304))
- `multipass exec` now returns the exit code of the command run inside the instance ([#4266](https://github.com/canonical/multipass/pull/4266))
- QEMU upgraded to version 10.0.3; VMs suspended with Multipass 1.16 resume transparently after the upgrade ([#4286](https://github.com/canonical/multipass/pull/4286), [#4416](https://github.com/canonical/multipass/pull/4416), [#4799](https://github.com/canonical/multipass/pull/4799), [#5084](https://github.com/canonical/multipass/pull/5084))
- Minimum resources for new instances raised to 512 MiB of memory and 1 GiB of disk, preventing silent cloud-init failures on undersized launches ([#5057](https://github.com/canonical/multipass/pull/5057))
- Clearer error messages from the daemon when client authentication fails ([#4157](https://github.com/canonical/multipass/pull/4157))
- Launch failures caused by network or firewall problems now link to the troubleshooting documentation ([#4518](https://github.com/canonical/multipass/pull/4518))
- Certificates for the client-daemon connection are now annotated and automatically regenerated when invalid or mismatched, and the GUI verifies the daemon's certificate ([#4226](https://github.com/canonical/multipass/pull/4226), [#4394](https://github.com/canonical/multipass/pull/4394), [#4329](https://github.com/canonical/multipass/pull/4329))

### GUI improvements

- Redesigned image catalogue on the launch screen, grouping releases per operating system ([#4474](https://github.com/canonical/multipass/pull/4474))
- Minimum RAM and disk sliders in the launch form adapt to the selected image type ([#4239](https://github.com/canonical/multipass/pull/4239))
- The terminal remembers its font size, and offers a "Select All" context-menu entry ([#4208](https://github.com/canonical/multipass/pull/4208), [#4211](https://github.com/canonical/multipass/pull/4211))
- New About section in the Settings tab ([#4420](https://github.com/canonical/multipass/pull/4420))
- GUI strings were extracted for localization ([#4797](https://github.com/canonical/multipass/pull/4797))
- Quitting from the tray brings the window to the front and no longer stacks multiple confirmation dialogs ([#5135](https://github.com/canonical/multipass/pull/5135), [#5148](https://github.com/canonical/multipass/pull/5148))
- GUI framework upgraded to Flutter 3.32 ([#4181](https://github.com/canonical/multipass/pull/4181))

## Removed functionality

The following features, deprecated in Multipass 1.16, have been removed:

- The LXD driver ([#4402](https://github.com/canonical/multipass/pull/4402))
- The libvirt driver ([#4365](https://github.com/canonical/multipass/pull/4365))
- Blueprints ([#4389](https://github.com/canonical/multipass/pull/4389))
- Appliances ([#4363](https://github.com/canonical/multipass/pull/4363), [#4120](https://github.com/canonical/multipass/pull/4120))
- The deprecated `mem` shortcut for the `--memory` option ([#4116](https://github.com/canonical/multipass/pull/4116))
- The deprecated `--all` option of `multipass info` ([#5032](https://github.com/canonical/multipass/pull/5032))

## Breaking changes

- CLI exit codes were unified: `multipass shell` and `multipass exec` propagate the exit code of the in-instance command, while 255 is reserved for Multipass' own failures ([#4567](https://github.com/canonical/multipass/pull/4567))
- Mount target paths are fully normalized before use; in particular, trailing slashes are now trimmed ([#4031](https://github.com/canonical/multipass/pull/4031))
- Symlinks in mounts that point outside the mounted folder are now denied instead of retargeted into the mount ([#4887](https://github.com/canonical/multipass/pull/4887))
- Key ordering in `--format json` output is no longer guaranteed ([#4777](https://github.com/canonical/multipass/pull/4777))
